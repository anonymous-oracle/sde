Mode Collapse Problem
Mode collapse in LLMs refers to a failure mode where the model produces overly similar,
repetitive, or low-diversity outputs, even when many different valid responses should exist.


The term comes from GANs: it is used analogously for LLMs to describe loss of output diversity.


Why it happens?
 ●   Reason: Model’s internal probability distribution
 ●   Models prioritize most probable, predictable responses
 ●   What it uses to decide what to say next, becomes “collapsed” around a few high-probability
     “modes” or options


                 Think of it as: A musician who knows thousands of songs, but only plays their top three hits.
Mode Collapse Problem

     Why this matters?

 ●    Mode collapse reduces the effectiveness of:
        ○    Self-consistency decoding,
        ○    Tree-of-thought,
        ○    Reflection loops.
 ●    Even with temperature sampling, most
      trajectories begin similarly.
 ●    Every AI gives the exact punchline!
 ●    They know hundreds of jokes (answers), but
      default to the safest one.

Mode Collapse Problem
How it happens?
 ●   Early-token lock-in.
       ○   The remainder of the trajectory collapses into nearly identical continuations.
       ○   This is analogous to beam search degeneration.


 ●   Sharp token distributions after RLHF. Preference tuning happens heavily sharpen probability mass
     around:
       ○   safe answers.
       ○   coherent reasoning styles.
       ○   popular chain-of-thought structures.


 ●   Language priors dominate reasoning priors. So verbalized reasoning often reflects:
       ○   common internet exposition styles, memorized reasoning schemas.
       ○   textbook proof templates.
Mode Collapse Problem

More examples:
 ●   "Pick a random number between 1 and 10" → 7, almost every time
 ●   "Pick a random number between 1 and 100" → 42 or 47, disproportionately
 ●   "Think of a random vegetable" → carrot, okra, broccoli
 ●   "Name a random country" → Japan or France
 ●   "Recommend a sci-fi novel" → Dune, Hyperion, or Three-Body Problem on loop
 ●   "Summarize this" → three bullets, regardless of source length
 ●   Endings of essays → "In conclusion" or "Ultimately"



 ●   Sometimes all models may not give similar outputs. Because, these models continuously
     get trained/tuned.
 ●   In some cases, temperature tuning and nucleus sampling also solves this.

 Manual evaluation (human review) of each summary would be
 time-consuming, costly and would not be scalable, so it is
 usually complemented by automatic evaluation.



 Many automatic evaluation methods attempt to measure the same qualities of text that
 human evaluators would consider.



 Those qualities include fluency, coherence, relevance, factual consistency, and fairness

Different Ways to Compute Metric Scores
Statistical Scorers

  ➢ BLEU (BiLingual Evaluation Understudy)
                                                                                       Check Module 1
  ➢ ROUGE (Recall-Oriented Understudy for Gisting Evaluation)
  ➢ METEOR (Metric for Evaluation of Translation with Explicit Ordering)                  (Session 5)

  ➢ Levenshtein distance scorer calculates the minimum number of single-character edits (insertions,
    deletions, or substitutions) required to change one word or text string into another.


      This is useful for evaluating spelling corrections, or other tasks where the precise alignment of
      characters is critical.

       Example: Levenshtein distance between “kitten” and “sitting” is 3
       since, at a minimum, 3 edits are required to change one into the other.

       kitten → sitten (substitution of “s” for “k”)
       sitten → sittin (substitution of “i” for “e”)
       sittin → sitting (insertion of “g” at the end).
Model-Based Scorers


 ●   NLI scorer: uses Natural Language Inference models to classify whether an LLM output is
     logically consistent (entailment), contradictory, or unrelated (neutral) with respect to a given
     reference text.
       ○ The score typically ranges between entailment (with a value of 1) and contradiction (with a
           value of 0), providing a measure of logical coherence.

 ●   BLEURT (Bilingual Evaluation Understudy with Representations from Transformers) scorer,
     which uses pre-trained models like BERT to score LLM outputs on some expected outputs.

Model-Based Scorers
G-Eval
It first generates a series of evaluation steps using chain of thoughts (CoTs) before using the
generated steps to determine the final score via a form-filling paradigm.

 ●       For example, evaluating LLM output coherence using G-Eval involves constructing a
         prompt that contains the criteria and text to be evaluated to generate evaluation steps,
         before using an LLM to output a score from 1 to 5 based on these steps.


 To generate evaluation steps:

     ●    Introduce an evaluation task to the LLM of your choice (eg. rate this output from 1–5 based
          on coherence)
     ●    Give a definition for your criteria (eg. “Coherence is the collective quality of all sentences in
          the actual output”).
Model-Based Scorers
G-Eval
After generating a series of evaluation steps:

 1. Create a prompt by concatenating the evaluation steps with all the arguments listed in
    your evaluation steps (eg., if you’re looking to evaluate coherence for an LLM output, the
    LLM output would be a required argument).

 2. At the end of the prompt, ask it to generate a score between 1–5, where 5 is better than 1.

 3. (Optional) Take the probabilities of the output tokens from the LLM to normalize the
    score and take their weighted summation as the final result.

  Step 3 is optional because to get the probability of the output tokens, you would need access to
  the raw model embeddings, which is not something guaranteed to be available for all model
  interfaces.

Prompt compression techniques: Basic
Prompt compression is not a single method, but a combination of techniques used to reduce
prompt length, optimize token counts and preserve key information for effective LLM inference.

 Example:
                 Original:
                 Customer John reported unstable internet for 3 days with video call disruptions.

 1. Extractive compression:
 selects the most relevant parts of the input while removing redundant or low-value content. It is
 supported by NLP techniques such as Named Entity Recognition (NER) and keyword extraction.

 NER helps identify important entities like “John,” while keyword extraction highlights critical
 terms such as “internet” and “video issues.” Together, these techniques help the model focus
 on high-value information.

                   John: unstable internet, 3 days, video issues

 2. Summarization

 Summarization converts extracted content into a concise and readable representation. Modern
 LLMs use abstractive summarization, where they understand the meaning of the input and
 rewrite it in a shorter form rather than copying text directly. This allows the model to preserve
 intent while reducing complexity.

 Token-level optimization reduces the number of tokens processed by the model by simplifying

Prompt security
Introduction
                          Prompt Safety vs. Prompt Security


     ❏   Prompt Safety: Preventing harm that a LLM might inflict upon the
         external environment

     ❏   Prompt Security: Protecting the LLM itself against harm and exploitation
         from malicious external actors

     ❏ Prompt safety needs to consider adversarial setting
        ❏ e.g., alignment mechanisms need to be resilient/secure against
           attacks
Prompt Security: Introduction

        Ensuring that Large Language Models behave as intended by protecting
        system prompts, user data, and tool outputs from manipulation or leakage.



 Key Threats

  ●   Prompt Injection: User input tries to override system instructions
  ●   Jailbreaking: Bypassing safety filters to generate restricted content
  ●   Prompt Leaking: Attempts to reveal system instructions or hidden policies
  ●   Backdoor Attack: Model behaves normally unless a hidden trigger activates
      unsafe behavior

Prompt Leaking
                               Scenario: A Customer Support Bot for a Bank

  Imagine a sophisticated AI chatbot used by a major bank to assist customers with account issues.
    The bot is designed to be helpful but also extremely secure, with strict rules against revealing
                            internal procedures or other customers' data.


Confidential System Prompt: The developer's system prompt for this banking bot might contain
sensitive instructions and placeholders for customer data.

Malicious Attack: A regular user interacts with the bot for a legitimate reason, providing their personal
data. However, an attacker crafts a prompt that looks like a normal query but has a malicious
instruction appended to it.

Sensitive Leak: The LLM, tricked by the overriding command, ignores its security protocols. Instead of
helping with the fraud claim, it executes the attacker's instructions and outputs the sensitive
information.
Prompt Leaking

         ●   Prompt leaking is a form of security exploit where an attacker designs a
             prompt to make an LLM reveal its underlying instructions or confidential
             data.

         ●   This is considered a subtype of prompt injection. Many companies and
             developers create complex, proprietary prompts that are valuable
             intellectual property, and prompt leaking can expose this sensitive
             information.

         ●   Prompt leaking aims to force the model to spit out information about its
             own prompt.

         ●   This can lead to leaking of either sensitive, private or information that’s
             confidential.
